GIT-SHARED-STATUS(1)

NAME
    git shared status - show the state of each shared file

SYNOPSIS
    git shared status [--peers] [--remote]

DESCRIPTION
    Shows each shared file with its path, ID and state, and what to do.

    First status receives the versions the peers announced: nothing is
    fetched unless there is something new, and the working tree is not
    touched. A note says when an announced version could not be
    received, or when the version of a peer must be merged: in both
    cases, update. A version announced by a repository that is not a
    peer of this one is not fetched from it: the note says to run
    'git shared update --peers' in that repository, which brings it here.

    For a file shared through a remote (beta) a "creator" line
    shows the repository the versions come from and, in brackets, how
    the latest version here compares with the last one seen there, and
    when it was seen ("same version, seen 2026-11-24 10:32"): same
    version; ahead (push); newer version on the creator (update);
    diverged (update, then push); not checked yet (status --remote).
    Without --remote, status never uses the network.

    If the authority of the file is a sovereign chosen with
    'git shared crown', the "creator" line shows only the creator, and an
    "authority" line shows the sovereign with the comparison. A change
    of authority received and not decided yet is an "authority -> <url>"
    line, with where it comes from and the command to accept or reject
    it: until then the latest version does not move past it.

    A "heirs" line lists the heirs of the file in order of succession
    (git shared crown --help, HEIRS). With --remote, if the authority
    does not answer, a note says which heir took its place (pull follows
    it), or that nobody did; if the authority is a sovereign and the
    creator answers again, a note says so.

    If the version chain of a file is missing here, status rebuilds it
    from the last version seen on the creator, without the network, or
    from a local peer, and says so. If nobody has it, a note says to
    unlink the file and link it again.

    aligned               you have the latest version: nothing to do
    new version to apply  a peer published a newer one: update
    applied, to commit    update applied it: commit
    to publish            you changed it on the latest version: publish
    diverged              you changed it on an older version, or two
                          peers published without seeing each other:
                          update, which merges
    merge in progress     update found a conflict: fix the file, git add,
                          update again
    pending commit        set, link, unlink or mv not committed yet:
                          commit, or restore .gitshared to cancel
    unlinked              declared here but not linked (a clone): link
    inconsistent          the file was deleted, or renamed without
                          'git shared mv', or .gitshared was edited by
                          hand, or no branch declares the file any more:
                          mv <old> <new> for a rename, unlink (with the
                          id, for the last case), or restore .gitshared
    suspended on this branch (...)
                          this branch is not one of the file's branches:
                          it is a regular file here. The real state is
                          in brackets. 'git shared branch' changes it.
    suspended on this branch (not declared here)
                          this branch does not declare the file (it was
                          created before set): the note says on which
                          branch it is shared. Nothing to do.

OPTIONS
    --peers
        Also shows, for each peer: same version; older version (publish);
        announced, not received yet (nothing to do: it will get it by
        itself); newer or different version (update --scan); no version
        yet (publish); no longer shares the file, or not found (prune);
        cannot be read now. Nothing is fetched from the peers or changed
        in them.

    --remote
        First fetches the version chain from the creator of each file
        shared through a remote, one fetch for each creator, as pull
        does, but without applying anything. If a creator cannot be
        reached a note says so, and the state uses the last version
        seen.

SEE ALSO
    git shared update --help, git shared publish --help
