GIT-SHARED-PULL(1)

NAME
    git shared pull - get the versions of the creator and apply them

SYNOPSIS
    git shared pull [-f] [--scan] [-c | -m <message>] [<path>]

DESCRIPTION
    Like 'git pull' = fetch + merge: for each file shared through a
    remote (beta), fetches the version chain of its creator, one
    fetch for each creator, then runs 'git shared update' with the same
    options. Only the version chain is fetched, not the project.

    The latest version of the creator stays in this repository: after a
    pull, or a 'git shared status --remote', update and status work
    without the network.

    If the file has a sovereign (git shared crown), pull fetches from
    the sovereign instead. A change of authority received is never
    applied by pull: it waits for 'git shared crown --accept' or
    '--reject'.

    If the creator cannot be reached, or no longer has the file, pull
    tries its heirs in order of succession (git shared crown --help,
    HEIRS): an heir that crowned itself is followed without asking, and
    the file is updated from there. Otherwise that file is not updated
    and pull fails, saying who could take over; the other files go on. Files
    without a creator are only updated, as with update. pull never asks
    for a password: it uses the credentials git already has.

    To finish or give up a merge (--ours, --theirs, --abort) no network
    is needed: use update.

OPTIONS
    -f, --force
        Overwrite local changes of the file.

    --scan
        Also fetch from every local peer, as 'update --scan'.

    -c, --commit
        Commit the applied files right away.

    -m <message>
        Commit right away with <message>.

EXAMPLES
    git shared pull -c

SEE ALSO
    git shared push --help, git shared update --help,
    git shared status --help, git shared crown --help
