GIT-SHARED-PUBLISH(1)

NOME
    git shared publish - invia la versione nuova ai peer

SINTASSI
    git shared publish [<path>]

DESCRIZIONE
    Per ogni file shared modificato e committato sopra l'ultima versione,
    crea una versione nuova e la annuncia a tutti i peer: un piccolo
    avviso va nella cartella .git del peer, che scarica la versione da
    se' al suo comando git shared successivo. Per un file gia' allineato
    l'avviso si riscrive dove manca.

    Il commit non pubblica mai: questo e' l'unico modo.

    Prima publish riceve cio' che i peer hanno annunciato. Se un peer ha
    pubblicato una versione che non segue la tua, lancia
    'git shared update' per unire le due versioni, committa e pubblica
    di nuovo. Un peer che non si raggiunge viene saltato, con un avviso:
    pubblica di nuovo piu' tardi. Un peer la cui .git e' un file (un
    worktree secondario) riceve la versione con git push.

    Senza <path>, tutti i file shared; con <path>, solo quello.

ESEMPI
    git commit -am "Corretto il timeout in common.h"
    git shared publish

VEDI ANCHE
    git shared update --help, git shared status --help
