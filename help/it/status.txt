GIT-SHARED-STATUS(1)

NOME
    git shared status - mostra lo stato di ogni file shared

SINTASSI
    git shared status [--peers] [--remote]

DESCRIZIONE
    Mostra ogni file shared con path, ID, stato e cosa fare. Gli stati
    sono scritti in inglese, come li stampa il comando:

    aligned               hai l'ultima versione: niente da fare
    new version to apply  un peer ne ha pubblicata una nuova: update
    applied, to commit    update l'ha applicata: commit
    to publish            l'hai modificato sull'ultima versione: publish
    diverged              l'hai modificato su una versione vecchia, o due
                          peer hanno pubblicato senza vedersi: update,
                          che unisce
    merge in progress     update ha trovato un conflitto: correggi il
                          file, git add, di nuovo update
    pending commit        set, link, unlink o mv non ancora committato:
                          commit, oppure restore di .gitshared per
                          annullare
    unlinked              dichiarato qui ma non collegato (un clone): link
    inconsistent          il file e' stato cancellato, o rinominato senza
                          'git shared mv', oppure .gitshared e' stato
                          modificato a mano, oppure nessun branch dichiara
                          piu' il file: mv <vecchio> <nuovo> per una
                          rinomina, unlink (con l'id, nell'ultimo caso),
                          oppure restore di .gitshared
    suspended on this branch (...)
                          questo branch non e' tra i branch del file: qui
                          e' un file normale. Lo stato vero e' tra
                          parentesi. 'git shared branch' lo cambia.
    suspended on this branch (not declared here)
                          questo branch non dichiara il file (e' nato
                          prima del set): la nota dice su quale branch e'
                          shared. Niente da fare.

    Prima status riceve le versioni annunciate dai peer: non scarica
    nulla se non c'e' niente di nuovo, e non tocca il working tree. Una
    nota dice quando una versione annunciata non si e' potuta ricevere,
    o quando la versione di un peer va unita: in entrambi i casi,
    update. Una versione annunciata da una repo che non e' un peer di
    questa non si scarica da li': la nota dice di lanciare
    'git shared update --peers' in quella repo, che la porta qui.

    Per un file condiviso attraverso un remoto (beta) una riga
    "creator" mostra il repository da cui arrivano le versioni e, tra
    parentesi, com'e' l'ultima versione di qui rispetto all'ultima vista
    li', e quando e' stata vista ("same version, seen 2026-11-24
    10:32"): same version (uguale); ahead (avanti: push); newer version
    on the creator (piu' nuova sul creatore: update); diverged
    (divergente: update, poi push); not checked yet (mai vista: status
    --remote). Senza --remote, status non usa mai la rete.

    Se l'autorita' del file e' un sovrano scelto con 'git shared crown',
    la riga "creator" mostra solo il creatore, e una riga "authority"
    mostra il sovrano con il confronto. Un cambio di autorita' ricevuto
    e non ancora deciso e' una riga "authority -> <url>", con da dove
    arriva e il comando per accettarlo o rifiutarlo: fino ad allora
    l'ultima versione non va oltre.

    Una riga "heirs" elenca gli eredi del file nell'ordine di
    successione (git shared crown --help, EREDI). Con --remote, se
    l'autorita' non risponde, una nota dice quale erede ne ha preso il
    posto (pull lo segue), o che nessuno l'ha fatto; se l'autorita' e' un
    sovrano e il creatore torna a rispondere, una nota lo dice.

    Se qui manca la catena delle versioni di un file, status la
    ricostruisce dall'ultima versione vista sul creatore, senza rete, o
    da un peer locale, e lo dice. Se nessuno ce l'ha, una nota dice di
    scollegare il file (unlink) e collegarlo di nuovo.

OPZIONI
    --peers
        Mostra anche, per ogni peer: stessa versione; versione piu'
        vecchia (publish); annunciata, non ancora ricevuta (niente da
        fare: la ricevera' da se'); versione piu' nuova o diversa
        (update --scan); nessuna versione (publish); non condivide piu' il
        file, o non trovato (prune); non leggibile adesso. Dai peer non
        scarica e non cambia nulla.

    --remote
        Prima scarica la catena delle versioni dal creatore di ogni file
        condiviso attraverso un remoto, un fetch per creatore, come pull,
        ma senza applicare nulla. Se un creatore non risponde lo dice una
        nota, e lo stato si ricava dall'ultima versione vista.

VEDI ANCHE
    git shared update --help, git shared publish --help
