GIT-SHARED-UPDATE(1)

NOME
    git shared update - riceve le versioni nuove e le applica

SINTASSI
    git shared update [-f] [--all] [-c | -m <messaggio>] [<path>]
    git shared update --abort [<path>]

DESCRIZIONE
    Riceve le versioni annunciate dai peer e scrive l'ultima nel file e
    nell'index. Scarica solo dai peer che hanno annunciato qualcosa.
    Non committa nulla, salvo -c o -m.

    Le modifiche non committate, anche quelle in staging, non vengono mai
    sovrascritte: update si ferma, salvo -f. Una versione applicata da un
    update precedente e non ancora committata non e' una tua modifica.

    Unione. Se hai modificato il file su una versione vecchia, o due peer
    hanno pubblicato senza vedersi, update unisce le versioni come
    git merge. Dopo un'unione pulita il file e' "applied, to commit":
    committalo, poi 'git shared publish'.

    In caso di conflitto il file riceve i soliti marker e git status lo
    mostra come non unito. Correggi il file, poi:
        git add <file>
        git shared update -c
        git shared publish
    Per rinunciare all'unione:
        git shared update --abort
    Il file torna quello dell'ultimo commit e l'unione sparisce, in un
    solo passo. Funziona anche un semplice
    'git restore -s HEAD -SW -- <file>', ma solo dal comando git shared
    successivo: una modifica messa in staging prima varrebbe come
    risoluzione.

    Senza <path>, tutti i file shared; con <path>, solo quello.

OPZIONI
    -f, --force
        Sovrascrive le modifiche non committate.

    --all
        Scarica da tutti i peer, non solo da quelli che hanno annunciato
        una versione nuova: per un avviso andato perso, per esempio
        mentre questa repo era spostata o non si raggiungeva.

    -c, --commit
        Committa subito i file applicati o uniti. Nient'altro di cio' che
        e' in staging entra nel commit.

    -m <messaggio>
        Come -c, con <messaggio>.

    --abort
        Rinuncia all'unione in corso: il file torna quello dell'ultimo
        commit, nell'index e nel working tree. Nessun fetch, e l'ultima
        versione non cambia. Senza <path>, tutti i file shared con
        un'unione in corso.

VEDI ANCHE
    git shared publish --help, git shared status --help
