GIT-SHARED-PUBLISH(1)

NAME
    git shared publish - send the new version to the peers

SYNOPSIS
    git shared publish [--remote <remote>] [<path>]

DESCRIPTION
    For each shared file changed and committed on top of the latest
    version, creates a new version and tells every peer about it: a
    small notice goes into the peer's .git folder, and the peer fetches
    the version by itself at its next git shared command. For a file
    already aligned, the notice is written again where it is missing.

    Committing never publishes: this is the only way.

    First publish receives what the peers announced. If a peer published
    a version that does not follow yours, run 'git shared update' to
    merge the two versions, commit, and publish again. A peer that
    cannot be reached is skipped, with a warning: publish again later.
    A peer whose .git is a file (a secondary worktree) gets the version
    with git push.

    Without <path>, all the shared files; with it, only that one.

REMOTE (PROTOTYPE)
    The first time, 'publish --remote <remote>' makes that remote
    repository the creator of the file: a new version records its URL
    and is pushed there. Only the version chain is pushed, never the
    project. The local peers receive the version as any other.

    From then on, for that file publish also pushes the chain to the
    remote of this repository (--remote, or origin), as a copy for whoever
    clones it, and to the creator, where the official versions are. The
    creator takes only a version that follows its own, and only from who
    can write there. If it refuses because it has a newer version, run
    'git shared update', commit and publish again. If you cannot write
    there, the version stays here (and in your remote) as a proposal.

    Without --remote, a file that has no creator stays local.

OPTIONS
    --remote <remote>
        The remote that receives the copy (default: origin). For a file
        without a creator, it becomes the creator.

EXAMPLES
    git commit -am "Fix the timeout in common.h"
    git shared publish

    git shared publish --remote origin    # first publish to the remote

SEE ALSO
    git shared update --help, git shared status --help
